# Current time (Phase 1)

`current_time` is read-only and default off. Both `read_only_tools.enabled` and `read_only_tools.policies.current_time.enabled` must be YAML booleans `true`; missing or other values leave it disabled. The example policy sets six calls per identity per 60 seconds. It uses the shared registry semaphore and the ordinary ten-second deadline, including queue time. The complete encoded registry result is capped at 2,000 characters; oversized results fail closed. An admitted, already-onboarded explicit request uses one tool call, follows the usual response and rate-limit path, and is not written to short-term history. Onboarding, forget, media, and crisis processing retain their existing ordering and behavior; private admission no longer depends on allowlist membership. The tool has no sender, identity, network, or memory access.

The closed arguments schema is `{"type":"object","properties":{},"required":[],"additionalProperties":false}`. Malformed JSON, duplicate keys and all fields, including timezone, offset, date, identity or recipient, are rejected. Each successful invocation samples the operating system clock once as an aware UTC instant and converts it with `zoneinfo.ZoneInfo("Asia/Shanghai")`; there is no local-time, fixed-offset, cached, network, or model fallback. Clock and timezone database errors produce the generic unavailable result. System clock accuracy and installed IANA timezone data are operational prerequisites; no independent accuracy guarantee is made.

Adapter data is compact ASCII JSON with exactly the ordered keys `date`, `weekday`, `time`, `time_of_day`, `timezone`, `utc_offset`. Date is `YYYY-MM-DD`, weekday is English Monday through Sunday, time is 24-hour `HH:MM:SS` truncated to seconds, timezone is `Asia/Shanghai`, and offset is the actual converted offset `+HH:MM` or `-HH:MM`. The periods are `night` at 00:00:00–05:59:59, `morning` at 06:00:00–11:59:59, `afternoon` at 12:00:00–17:59:59 and `evening` at 18:00:00–23:59:59. The registry wraps this string as `{"status":"ok","data":"..."}`. A validated result is rendered as `YYYY-MM-DD Weekday HH:MM:SS (period, Asia/Shanghai, UTC+HH:MM)`; errors produce `当前时间暂不可用，请稍后再试。` A displayed reading is a snapshot, not a continuously updated clock.

Matching is a full-message match after trimming surrounding whitespace, case-insensitive for English, with at most one trailing `?`, `？`, `!`, `！`, `。` or `.`. Supported exact forms are:

- `现在几点`, `现在几点了`, `现在几点钟`, `现在是什么时间`, `现在的时间`, `当前时间`.
- `what time is it`, `what time is it now`, `what is the current time`, `what's the current time`, `current time`.

This deliberately rejects embedded requests, compound questions, alternate locations or zones, dates, and looser forms. When enabled, the full-message ambiguous forms `几点`, `what time`, `现在几点在` followed by 1–40 characters, and `current time in ` followed by 1–40 characters receive a fixed request for confirmation of Asia/Shanghai instead of a clock reading. The same whitespace, case and optional punctuation rules apply. Other false negatives proceed through ordinary handling. A standalone phrase can be treated as a time request even if the speaker intended something else: that is a possible false positive. No location is inferred. The model may also try the tool, but the same exact-request check and validation apply; the deterministic formatter handles successful or unavailable tool results.

The instruction prohibiting unsupported exact current-time assertions is probabilistic. A synthetic test with a deliberately noncompliant model produced an exact time while the feature was off; this demonstrates the residual but is not a measurement of real model behavior. Ordinary and ambiguous model responses are unconstrained and can also make unsupported claims, including when the feature is enabled but the request is not matched. A separately reviewed deterministic guard is required before deployment if the acceptance scope requires eliminating those claims. The feature-off route otherwise retains disabled-tool exposure and ordinary processing; the instruction changes the prompt. No live model or chat evaluation was performed.

A later, separately authorized deployment window must review this diff and acceptance scope, verify host clock health and installed IANA data, flags and rollback, shared-queue and end-to-end latency, existing tools and safety behavior. It must test a real private-chat explicit time request when enabled and disabled parity when off, under that window's own authorization. Disable the individual policy to roll back this capability; the global switch affects other read-only tools too.
