# Weather lookup (disabled by default)

The read-only `weather_lookup` tool requires both `read_only_tools.enabled: true` and `read_only_tools.policies.weather_lookup.enabled: true`. Both default to `false`. It only runs in the existing admitted, non-crisis DeepSeek tool path. It requires the city and any qualifier to be present in the current user message; it does not look up a remembered or guessed location. It supports local today and tomorrow. Ambiguous places require a more specific city, province or country; unavailable data is never replaced with a guess. The reply discloses the external lookup and includes the source, licence, forecast period, provider timezone and units.

The only endpoints are Open-Meteo geocoding and forecast. Requests transmit the requested city to geocoding and the resulting coordinates to the forecast API. The adapter does not log request URLs, locations or response bodies. Its bounded cache is in memory only, indexed by normalized city and local forecast date, and is valid for less than ten minutes. The existing tool loop does not store tool-assisted turns. The adapter also applies process-local limits of 300 provider requests/minute, 2,000/hour and 5,000/day; other applications sharing the IP may consume the same provider quota.

[Open-Meteo's terms](https://open-meteo.com/en/terms) permit the free API only for non-commercial use, require CC BY 4.0 attribution, and state limits of fewer than 600 calls/minute, 5,000/hour and 10,000/day. They also state that provider webserver logs can contain geographical coordinates and are deleted after 90 days. [Pricing](https://open-meteo.com/en/pricing) lists a monthly limit of 300,000 free calls. Eligibility for the actual deployment's use has not been established; confirm it before enabling. No API key is used.

Rollback: set `read_only_tools.policies.weather_lookup.enabled: false` (or set the global `read_only_tools.enabled: false` to disable all read-only tools). To remove the implementation entirely, return to `ai/companion-tool-contract` at `8d82cbb45ff52a60da3fc129a60c64feae7d95ac` through the normal, separately authorized deployment process. No data migration is required. Do not restart services as part of development or testing.
