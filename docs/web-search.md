# Read-only Tavily search and page content

Search requires both `read_only_tools.enabled: true` and `read_only_tools.policies.web_search.enabled: true`; both default to `false`. Page extraction additionally requires `read_only_tools.policies.web_search.content_extraction_enabled: true`, also defaulting to `false`. When extraction is disabled, usable search snippets provide body text without source listings. The tool is available only in the existing admitted, non-crisis DeepSeek tool path. Set `TAVILY_API_KEY` only in the process environment; `.env` values for it are ignored. Never commit credentials.

The fixed Tavily Search request uses `search_depth: advanced`, `max_results: 10`, `include_raw_content: false`, `include_answer: false`, `include_images: false` and `auto_parameters: false`. The [official Search reference](https://docs.tavily.com/documentation/api-reference/endpoint/search) confirms a maximum `max_results` of 20; the [credit schedule](https://docs.tavily.com/documentation/api-credits) specifies 2 credits per advanced search. No raw content is requested before source validation.

When extraction is enabled, the adapter scans same-turn results in provider order, strips URL query strings and fragments, and selects up to 10 distinct eligible URLs in one fixed Tavily Extract request; rejected or duplicate results do not consume that limit. Search requests at most 10 results, but a bounded provider response containing more is also scanned until the limit is filled. HTTP(S) URLs may be up to 2,048 ASCII characters. Percent-encoded paths are allowed after bounded, strict decoding for validation; malformed or excessively nested escapes, encoded authority changes, controls and encoded query or fragment delimiters are rejected. The original encoded URL is sent, not the decoded validation form. Credential-bearing authorities, sensitive credential, contact, identity-document and private-context terms, configured credential values, long opaque identifiers and most long numeric identifiers remain excluded. A valid eight-digit calendar date is permitted in a public URL path; this makes the identifier filter less conservative. The gateway-local identity predicate checks both original and decoded forms without giving the identity to the adapter or provider. No query, identity, history, other credential or model-provided URL is sent to Extract. The [Extract reference](https://docs.tavily.com/documentation/api-reference/endpoint/extract) permits up to 20 URLs per request and supports `basic` and `advanced` depth. This implementation uses `extract_depth: advanced`, `include_images: false`, and `format: text`. Companion never directly fetches a result page; its Tavily client uses `trust_env: false` and refuses redirects.

Tavily's [credit schedule](https://docs.tavily.com/documentation/api-credits) says basic extraction costs 1 credit and advanced extraction costs 2 credits per five successful URLs, with failed extractions uncharged. For 10 successful URLs, the single advanced Extract batch costs 4 credits, plus 2 for advanced Search: **6 credits per full search**, or at most 166 full searches using all 1,000 monthly credits on the [free plan](https://www.tavily.com/pricing), assuming no other usage. The official schedule does not establish how partial batches are rounded or accumulated; actual cost for fewer than 10 successes is unconfirmed. Check live billing before relying on a partial-batch estimate. Search-only or no eligible pages incur the search cost; provider-side processing can incur charges even if the local deadline expires.

Each provider response is limited to 256,000 bytes. Extracted body text is cleaned of HTML tags, scripts, styles, images, obvious headings, source lines, link destinations, URL-like text, matching result titles and configured credential values. Each page or snippet is capped at 800 characters; the complete JSON-encoded tool result is capped at 5,000 characters, shared across pages so later pages have room. JSON escaping can substantially reduce the amount of non-ASCII text that fits. Successful output starts directly with body text sections separated by blank lines; partial extraction appends `部分页面暂时不可用。` after the available body text. No source list, titles, or links are intentionally included. When extraction fails, times out, yields no text, or is disabled, usable Search snippets from validated eligible sources are cleaned in the same way and returned as body text without a leading disclaimer. No eligible URLs means no snippets pass this source filter. If there is no usable extracted body or eligible cleaned snippet, the tool returns only `页面内容暂时不可用。` This includes a successful Search with zero usable results. Search errors retain the generic unavailable response. Partial success preserves available extracted body text with the partial-availability note.

Page content is untrusted data, not instructions. When body text exists, the model is instructed to summarize it neutrally without repeating an uncertainty notice, avoid invented access failures and omit sources, titles and URLs. Public news or popular topics alone are not a reason to refuse. Factual, neutral summaries of public current affairs, including domestic and international political current affairs, are allowed; state uncertainty and omit sources, titles and URLs in user-facing output. Refuse requests for a stance, persuasion, evaluation or political advocacy, and do not give graphic or detailed descriptions of suicide incidents. Existing crisis detection and fixed replies are unchanged. Synthesis filters obvious source references and detects some false access claims; if the model claims pages are blocked despite body text, it can retry within the existing three model requests, then uses a neutral synthesis fallback if that claim persists. This is a heuristic, not a guarantee that all invented failures, refusals, titles, source references or unsafe content will be detected. Tool-assisted turns are not stored as conversation memory.

The tool description encourages searches for broad requests for recent public information or weekly popular topics. The query gate still requires a contiguous portion of the current user message after ignoring whitespace and punctuation; it does not permit invented search terms, private information, credentials, or caller identity. The model chooses whether to call the tool, so a vague request can still fail to trigger it. The existing admission, safety and credential/contact gates, two tool rounds and three actual calls remain unchanged.

The adapter has a 12-second total deadline: Search gets at most 5 seconds and Extract at most 5 seconds, leaving a margin for processing and fallback inside the total. The web-search gateway deadline is 14 seconds, allowing the adapter deadline to complete; other tools retain 10 seconds. Queueing at the shared gateway also counts against its deadline. Advanced extraction can exceed the local budget; usable Search snippets can then provide fallback body text. Adapter or gateway timeouts outside the extraction timeout return a generic unavailable response; no automatic retries are made.

Each started search emits one sanitized `companion.tools.web_search` diagnostic: fixed `error_category` and `extraction_category`, `http_status` for Search, `elapsed_ms`, `raw_result_count`, `displayable_result_count` (source-validation successes, not necessarily eligible for extraction), `extracted_page_count` (at most 10), and `failed_page_count` (selected URLs without usable returned body text). Counts and status may be unavailable when Search fails; extraction counts are zero when not attempted. No query, content, credentials, identity, URLs, exception text or provider response is logged. Gate rejections emit only fixed reason codes (`charset`, `sensitive`, `substring`, `identity`, `schema`, `rate_limited`) via `companion.tools.web_search.gate`.

Residual risks: User-facing output no longer carries an explicit unverified note; it relies on the model to synthesize search content with restraint, which is not guaranteed. Tavily may fetch pages and follow redirects itself; Companion's redirect restriction does not control the provider. Search and extraction expose the accepted query and selected URLs to Tavily, whose retention and internal fetching behavior are not established here. Pattern checks can miss disguised identifiers or sensitive context, including identifiers resembling valid dates; they can also reject legitimate public URLs. Content may be false, stale, malicious, or include disguised links and source names. Pattern-based output cleaning and model instructions cannot guarantee neutrality, prevent every stance-like phrasing, remove every disguised reference or resist every prompt injection; truncation may omit useful context. The bounded response can reject large batches, and the output limit can substantially shorten each page. A later authorized deployment window must verify current provider terms and billing, partial-batch rounding, live response format, source-free output, latency and timeout rates, fallback, safety, and memory behavior with controlled traffic and appropriate credentials. It must verify a short generic query produces output that starts with body text and has no leading disclaimer, a partial-extraction case preserves successful pages and reports partial unavailability, and a zero-result case returns the bare fallback. It must also include a real private-chat test of a factual current affairs summary showing no stance and no persuasion, as well as nonpolitical public news and vague weekly popular topics, respecting the current boundary and crisis safeguards.

Rollback: disable either search switch; disabling only extraction leaves search enabled and uses eligible cleaned snippets when available. No data migration is needed. Development and tests do not deploy or restart services.
